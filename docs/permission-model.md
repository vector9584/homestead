# 权限模型

这套系统的权限只有**一个维度**：用户名 → 他能进的目录名列表。

## 数据

一个 JSON 文件，路径 `.acl/perm.json`：

```json
{
  "alice": ["*"],
  "bob":   ["notes", "photos"],
  "carol": []
}
```

- key：用户名。必须和密码文件里的用户名一致。
- value：目录名数组。目录名就是磁盘上的文件夹名，一字不差。

没有角色表、没有分组、没有继承。要加一个人，就在这个文件里加一行；要收回权限，就把目录名删掉。

## `["*"]` 是一个标记，不是两个

`["*"]` 同时代表两件事：

1. 这个人是**管理员**——能进后台，能改别人的权限；
2. 这个人**能看到全部页面**——包括以后新增的目录。

这两件事为什么不拆开？因为在这套系统里它们本来就是一件事：一个需要管全部页面的人，不可能被限制只能看其中几个。

**拆开会产生什么？** 想过这些组合，每一个都是 bug 温床：

| 组合 | 问题 |
|---|---|
| 管理员 + 只能看 2 个页面 | 他在后台能给自己加页面吗？能加=限制无效；不能加=后台半残 |
| 非管理员 + 能管别人 | 那他就是管理员，只是名字不同 |
| 管理员 + 看不到某页 | 卡片墙上不显示，但他知道路径，直接敲能进吗？ |

结论：**不拆。** 代价是"管理员不能只被授权看部分页面"，收益是后台不需要处理组合状态，代码里只有一个判断：

```php
$isAdmin = in_array('*', $dirsOf($user), true);
```

## 四条硬规则

全部在后端（`api.php`）实现。前端只负责把不可用的按钮设成 `disabled`。

### 规则 1：主账号不可被任何人改动

目标用户是主账号时，改密码 / 改配置 / 删账号 —— 一律拒绝，不管操作者是谁。

主账号要改自己的密码，走**独立的「改密码」入口**，那个入口不经过上面这套判断。

### 规则 2：管理员平级，谁也管不了谁

操作者是管理员、目标也是管理员、目标是他人 → 拒绝。

"平级"不是"可以互相管"，是"谁也不能管谁"。要动另一个管理员，只能由主账号来动。

### 规则 3：改自己的密码永远允许

不受规则 1、2 影响。否则一个管理员登进去连自己密码都改不了。

### 规则 4：开放目录恒勾选，不可取消

配置界面上，开放目录（比如暂存区）始终勾选且 `disabled`。

它是公共入口，不该被某个人的配置关掉；也不该因为某人的配置被"打开一次又关掉"。

## 判定表

实测跑过的四个组合（`alice` 是主账号，`bob`、`carol` 是管理员）：

| 操作者 | 目标 | 操作 | 结果 |
|---|---|---|---|
| `bob` | `carol` | 改密码 / 改配置 / 删账号 | **403** |
| `alice` | `carol` | 改密码 / 改配置 / 删账号 | 200 |
| 任何人 | `alice` | 改密码 / 改配置 / 删账号 | **403** |
| 任何人 | 自己 | 改密码 | 200 |

判定顺序很重要：**先判目标是不是主账号，再判是不是同级**。反过来的话，操作者是主账号时会先被"同级"挡住。

## 前端要做什么

只有两件：

1. **`disabled`，不是变灰。** 只是变灰的话，键盘 Tab 还能聚焦到它，回车就提交了。
2. **配置界面二选一。** 打开"管理员"开关时，页面勾选列表整体 `disabled` 并置灰；关掉开关，勾选列表恢复。两者从不并存。

## 匿名请求必须由服务端过滤

这条是踩过的，不是理论。

**前端过滤不算过滤。** 卡片墙上「游客只看见开放页面」如果实现成「拿到全部目录 → 在 JS 里 `.filter()` → 不画出来」，那目录名、每个页面的标题和描述**已经进了浏览器**。打开 DevTools 就能看全。

三个真实存在的口子，同一个病：

| 口子 | 泄露了什么 |
|---|---|
| `/_ls/` 目录列表接口 | 全部目录名、mtime，包括该登录的、该隐藏的 |
| 身份接口的匿名分支 | 每个目录的可见性（开放/登录/隐藏）、排序、**标题和描述** |
| 一个免登录的工具页 | 页面本身（数据接口有 401，但界面结构和入口全露） |

第二条最容易被忽略，因为「可见性表」看起来不像敏感数据。但它连「这里有个婚礼指南页面」这种话都说了。

### 先查拒绝规则有没有被前面短路

当时那行代码是这样的（伪代码）：

```php
// 1. 磁盘上不存在这个路径 → 放行，交给 nginx 出 404
if (!realpath($abs)) { return 200; }

// 2. 凭据目录和目录列表接口：一律拒
if ($seg === '.acl' || $seg === '_ls') { return 401; }
```

`/_ls` 是 nginx `autoindex` 的**虚拟前缀**，磁盘上根本没有这个目录 → 第一个判断就 `200` 返回 → 第二个永远执行不到。

**写了拒绝，被前面的放行短路了。**

判据：只要安全判断依赖「路径存不存在」，任何虚拟前缀都会走成「不存在 → 放行」。所有拒绝规则必须排在放行之前。

### 修法

虚拟前缀先映射回它背后的真实路径，再走同一套 `vis` 判定：

```php
if ($seg === '_ls') {
    $sub = 取出 /_ls/ 后面的第一段；
    if ($sub === '') {
        // 顶层清单（含所有目录名）：要登录
        return $me === null ? 401 : 200;
    }
    $seg = $sub;
    $uri = '/' . $sub . '/';   // 交给后面的 realpath + vis，和直接访问该目录同权
}
```

`$uri` 必须一起改，否则下一段 `realpath` 检查的还是 `_ls/xxx`，照样误放行。

匿名分支按 `public` 收窄，三个字段都要收：

```php
$vis = array_intersect_key($vis, array_flip($pub));
$met = array_intersect_key($met, array_flip($pub));
$ord = 过滤到「open 目录 + 可见外链的 key」;   // 漏了外链 key，相关卡片会从首页消失
```

### 收窄之后首页还能用吗

能，但前端要改一处。目录接口 401 时别回落到硬编码列表（那样游客会少一半卡片），改成用身份接口给的可见表生成卡片：

```js
function fallbackRender(){
  var vis  = VIS || {};
  var base = Object.keys(vis).length ? Object.keys(vis) : FALLBACK;
  var dirs = base.filter(canSee).map(做卡片);
  render(dirs, []);
}
```

游客拿到的 `VIS` 只有开放项，正好就是要显示的卡片 —— 后端收窄反而让前端不用再判断。

### 验收

匿名、普通用户、管理员三档，每种路径都打一遍：

```
路径            匿名   普通用户   管理员
/               200    200        200
/_ls/           401    200        200
/_ls/<开放目录>/  200    200        200
/_ls/<隐藏目录>/  401    401        200
/_ls/<后台目录>/  401    401        200
/工具页/         401    401        200
/后台/           401    401        200
/不存在的路径     404    404        404
```

**最后一行不能漏。** 收窄权限很容易把「未知路径」也变成 401 —— 那样谁敲错个地址都会先看到登录框。

## 常见实现错误

- **只在 PHP 里判断，没有 `disabled`**：用户会反复点一个永远失败的东西。
- **只在 `disabled` 上判断**：手搓请求直接过。
- **「不存在就放行」写在拒绝规则之前**：虚拟前缀（目录列表、健康检查这类）全都走成放行，写了拒绝也没用。
- **匿名分支把完整可见性表返回出去**：前端只画开放项，但隐藏目录的名字和标题已经给出去了。
- **用 session 里的用户名做 `isset` 检查但不比对**：`you can pass any username`。
- **JSON 文件权限过宽**：`.acl/` 必须只有 nginx/PHP 用户可读，`perm.json` 权限 `640` 起步。
- **目录名做了 trim / 大小写归一但比对时不做**：`Photos` 和 `photos` 会在不同地方被当成两个目录。
